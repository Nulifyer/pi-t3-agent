T3-only Pi/Juiced source audit and implementation
2026-11-09, version 0.2.0

Requested outcome

T3 is the sole user interface. Pi supplies the runtime and transport to Juiced.
Preserve T3's stronger tools, support other threads and models, discover models
without operator-maintained lists, and reload shared resources without restarting
the application. The user authorized implementation in this project, prohibited
T3 Code source changes, and later authorized replacement of this host's Pi setup
and live testing against its existing Juiced server.

Coverage

Every original production source file, installer entrypoint, test, manifest, CI
workflow, README, verification document, and project agreement in this repository
was inspected. The new modules below were reviewed and exercised through their
owning behavior. The review traced the installed T3 Pi adapter, generated MCP
bridge, discovery and text-generation paths, model/thinking metadata, runtime
policy, MCP authorization, thread/handoff delivery, and comparisons with the
Codex, Claude, and ACP integration paths. This is not a claim to have reviewed
every unrelated file in the T3 monorepo.

T3 source baseline: 0.1.7, application commit 322f6544dfad. Relevant current
upstream Pi paths were also inspected at 7b248349bdc066b1488f52083662597ab22d6fe3.
Pi source/API baseline: 1.5.0. Juiced's catalog, capabilities, serving options,
health, and worker metadata contracts were checked against its source.

Production ownership

- scripts/install.mjs: validation, narrow configuration merging, backups,
  legacy adoption/retirement, manifest upgrades, T3 profile connection, removal.
- install.sh and install.ps1: platform entrypoints into the same Node installer.
- extensions/index.ts: assembly of the package's supported extensions.
- extensions/t3-context.ts: T3-first guidance and shared ~/.agents/AGENTS.md.
- extensions/resource-reload.ts: resource monitoring, supported reload command,
  idle deferral, and workspace-trust UI command.
- extensions/lib/resource-state.ts: bounded resource roots, metadata fingerprints,
  symlink handling, and filtering generated model changes out of resource reload.
- extensions/juiced-provider.ts: bounded discovery bootstrap, periodic refresh,
  cache reuse, selected-model metadata alignment, status and refresh commands.
- extensions/lib/juiced-catalog.ts: one mapping from Juiced's model and serving
  metadata into Pi model definitions.
- extensions/lib/profile-state.mjs: generated native model snapshots and shared
  installation/discovery locking, stale-writer rejection, and publication rollback.
- extensions/agent-tools.ts and lib/command-sessions.ts: saved conversation plans,
  bounded managed commands, process lifetime, stdin, output, timeout and stop.
- extensions/ask-user.ts: T3 extension UI questions with choices or free text.

T3 retains ownership of its generated bridge, credentials, authorization, browser,
devices, worktrees, delegated tasks, schedules, PR links and watches, UI projection,
and conversation orchestration. Pi retains its supported transport and native
model cache. No generated T3 bridge is shipped in this repository.

Findings addressed

1. T3 tools were removed by this package's second allowlist.
   The old tool-loadout.ts replaced the active tools, hiding thread search/read/
   send/wait and cancellation. A real-Pi reproduction returned "Tool ... not
   found" until discovery occurred. Another server's discovered tool disappeared
   on the next turn. That implementation is removed. Guidance now preserves the
   native loadout and names only the current session's tool system. Explicit Pi
   CLI exclusions still apply. Real bridge tests execute a thread read directly
   and retain another extension across turns.

2. T3's cold and refreshed catalogs depended on an already warmed Pi cache.
   T3 launches discovery with --offline. The package now bootstraps only the
   configured Juiced metadata independently of unrelated OAuth refreshes. It
   refreshes periodically while idle and supports /t3-refresh-models. An explicit
   PI_T3_OFFLINE opt-out prevents metadata requests, including this bootstrap.
   The actual T3 provider now sees the host's discovered models.

3. Extension-free T3 helpers could not select extension-only models.
   Discovery now produces native models.json entries from the same catalog
   mapping. T3's restricted helper can select a discovered model with extensions
   and tools disabled. Generated entries are not a manually maintained model
   list. User overrides and authentication remain preserved. Runtime generation,
   upgrades, and removal share ownership rules and a profile lock.

4. Catalog eligibility and limits were incomplete.
   Explicit unavailable/incompatible/incomplete-artifact entries are excluded.
   Serving context remains per parallel slot, bounded by the architecture, with
   no arbitrary 65,536-token cap. Advertised output limits are honored. The
   conservative fallback applies only when output limits are unknown. Capability
   labels are declarations, not model conformance evidence. Retired selections
   are stopped with a T3 notice rather than silently redirected to another model.

5. Registry refresh left the active model's old context metadata in use.
   Refresh now reapplies the native snapshot and aligns the same selected model
   with updated metadata. Selection identity remains unchanged. The integration
   check changes context limits and confirms the active Pi model uses them.

6. Skills, descriptions, additions/removals, instructions, and extension code
   did not reload automatically. /reload over RPC reached the model as text.
   The package now uses Pi's supported command-context reload API, invoked by
   an idle-boundary monitor or /t3-reload. It does not infer reload completion
   from a model's response. Tests cover additions, edits, removals, extension code,
   an active response, native session identity, retained plans, and running jobs.
   The host's real ~/.agents/skills path was verified without model turns.

7. Reload previously terminated the package's managed commands.
   A process-local, session-scoped command owner survives resource reload. Real
   session exit/replacement still closes commands. Completed jobs are evicted
   within the 32-entry retention limit instead of requiring a new conversation
   after 32 starts. Concurrent limits count processes whose exit is unobserved.

8. T3 configuration could be invalid or point at the wrong profile.
   New provider instances include driver=pi. The installer connects the exact
   agent directory through T3's environment schema and preserves other variables,
   providers, and existing launch arguments. Settings comparison is insensitive
   to JSON object property ordering. Removal cleans newly created empty envelopes
   while retaining concurrent operator edits.

9. Older global extensions would keep the defective behavior after an upgrade.
   Recognized legacy files require explicit migration, receive private backups,
   and are retired. The existing provider can be adopted during a recognized
   legacy Juiced migration without changing credentials or default selection.
   Edited/unknown files are preserved. Uninstall restores the retired source.
   Previously owned obsolete source files are removed only after hash validation.
   The authorized host migration retired the old global copies; all ten installed
   extension sources matched the repository at installation verification.

10. The question tool forced invented choices for open questions.
    Choices are optional; free text uses Pi's input UI through T3. Both routes
    were exercised. This remains a single-question tool, not a claim to match
    every provider's native multi-question interface.

11. Project trust depended on Pi's terminal interface.
    /t3-trust now asks through T3 and uses Pi's public ProjectTrustStore for the
    current workspace. It refuses to override an explicit --no-approve launch
    policy. Pi's reload API intentionally retains the current trust decision;
    newly granted trust takes effect after that thread's agent restarts/resumes.
    Tests confirm native resume retains the conversation and loads the approved
    project extension. It does not grant blanket trust or restart T3.

12. The previous integration check only streamed one canned text reply.
    Coverage now includes real tool execution, several turns, model lifecycle,
    restricted helpers, resource and extension reload, questions and trust.
    CI uses a small handwritten contract fixture. The same scenarios were also
    checked with the installed T3 build's recovered bridge outside Git.

Verified results and limits

See verification.md for the exact suite and live-probe results. Focused tests and
real-Pi integration tests pass locally. The host was migrated with private
backups, preserving the selected provider/model and unrelated T3 providers.

The actual T3 capability response advertises cross-provider child-task support
for the enabled Pi instance and lists the four Juiced models plus its default
entry. A live Juiced model completed the T3 bridge thread-read round trip with a
controlled read-only target and returned the expected marker. Real production
thread histories were not used for this model experiment. No real delegated
child, schedule, PR watch, browser tab, or device operation was launched by the
verification process.

The original default model invoked the read tool but stalled before its final
reply. A ready model discovered from the same server completed the round trip.
The original default remains unchanged. The cause of its response latency was
not established; this audit does not claim that every model was qualified.

Remaining T3-owned differences

- Pi's provider deliberately hides T3's Plan-mode toggle. Native plan events and
  the plan panel are not emitted for the custom saved-plan tool. The early review
  was narrowed accordingly: this is a missing native feature, not proof of a
  visible Plan button silently failing. The package documents the distinction.
- Managed commands render as generic tool results and use pipes rather than a
  PTY. T3's Stop interrupts the agent; independent command sessions have their
  own stop/timeout/session lifetime. The package does not pretend they are native
  T3 background terminal activities.
- Native subagent controls and UI projection differ between Pi, Codex, Claude,
  and negotiated ACP agents. T3's MCP delegation remains the cross-provider route.
- This package can refresh the active runtime's resource inventory, but T3 owns
  its picker snapshots. An open picker may need its provider refresh action.
- Actual browser/device UI rendering and every model capability require further
  acceptance in the relevant T3 environment. Hosted Windows/macOS results were
  not generated by this local pass.

These differences require T3 adapter work or model/server qualification. The
user explicitly prohibited T3 application changes. They are documented limits,
not hidden by renamed tools or claims of complete Codex/Claude native parity.
